# 分类处理、最终确认与发起群聊

P0 完成前置信息后直接读取本文件；P1/P2 在自助排查全部结束且未达到高置信停止条件后读取。未经本文件规定的最终确认，不得执行建群。

## 目录

- 6. 按分类动作处理
- 7. 最终确认
- 8. 发起群聊

## 6. 按分类动作处理

| `type_action` | 处理方式 |
|---|---|
| `create_chat` | 进入最终确认 |
| `redirect` | 展示并尝试读取服务端链接；达到高置信停止条件则结束，否则回到分类阶段选择 `create_chat` 分类 |
| `join_group` | 展示服务端返回的目标群和入群链接，协助加入后结束；不创建新群 |
| `switch_tenant` | 使用服务端返回的目标租户回到第 2 步，重新分类、创建追踪工单并执行自助排查 |

- 飞书文档或 Wiki 使用可用的飞书文档能力读取，其他链接使用浏览能力。
- 处理 `redirect` 时，先向用户展示服务端链接，再尝试打开并提炼与当前问题相关的事实、适用条件、操作步骤和风险，同时展示更新后的解决置信度及依据。
- 若 `redirect` 链接可读且内容使解决置信度达到至少 90%，按高置信停止条件结束。若链接缺失、打开失败，或内容不足以使解决置信度达到至少 90%，将链接、已提炼内容或失败原因以及置信度不足的依据纳入 `self_help_summary`，保留当前 `oncall_flow_id` 和已有自助排查结果，然后回到第 3 步寻找 `type_action=create_chat` 的分类。
- 回退分类时优先在当前区域选择与问题最匹配的 `create_chat` 分类；当前区域没有候选时查询全部区域并自主选择最匹配候选。更新区域、分类、选择依据、`type_action` 和服务端后续处理字段后直接进入第 7 步，不重新调用 `flow create`，也不重复五项自助排查。
- 整个租户都没有 `create_chat` 分类时，说明无法按服务端分类创建群聊，不猜测分类 ID，并请用户补充产品信息或确认是否更换租户。
- 其他后续处理字段缺失或不可用时说明原因，不猜测替代值；`join_group` 不得改为建群，`switch_tenant` 缺少目标时请用户确认。检测到租户循环跳转时停止并请用户确认。

## 7. 最终确认

仅 `create_chat` 处理方式且此前未达到高置信停止条件时需要用户明确确认。先按固定顺序完整展示六类资料的最终状态；即使没有内容，也不得省略“工单记录、聊天记录、公告、智能问答、文档检索、工单知识”中的任何标题。每类按实际情况展示“已找到：<来源 + 关键结论>”“未找到”“已跳过：<原因>”或“查询失败：<原因>”，不要用索引摘要或推测补造内容。若由 `redirect` 回退，追加展示分类跳转链接、提炼结果或读取失败原因以及未达到高置信的依据。再紧凑展示升级信息：

```text
自助排查资料状态：
- 工单记录：<已找到：来源 + 关键结论 | 未找到 | 已跳过：原因 | 查询失败：原因>
- 聊天记录：<已找到：来源 + 关键结论 | 未找到 | 已跳过：原因 | 查询失败：原因>
- 公告：<已找到：公告类型 + 与当前故障相关的影响或处理要求 | 未找到 | 已跳过：原因 | 查询失败：原因>
- 智能问答：<已找到：关键建议 | 未找到 | 已跳过：租户未开启或 P0 | 查询失败：原因>
- 文档检索：<已找到：文档标题/链接 + 关键步骤 | 未找到 | 已跳过：租户未开启或 P0 | 查询失败：原因>
- 工单知识：<已找到：Artifact 名称/.md 链接/所属租户 + 原因、方案、排障路径或最佳实践 | 未找到 | 已跳过：P0 | 查询失败：原因>
- 分类跳转资料：<链接 + 提炼结果或读取失败原因 + 置信度不足依据，仅 redirect 回退时展示>

请确认是否发起 Oncall：
- 工单等级：<priority>
- 产品租户：<tenant_name>(<tenant_id>)；依据：<tenant_selection_reason>
- 工单 ID：<oncall_flow_id>
- 问题区域：<region_display_name>；依据：<region_selection_reason>
- 问题分类：<question_type_name>(<question_type_id>)；依据：<question_type_selection_reason>
- 问题描述：<trigger_message>
- 自助排查结论：<self_help_summary>
- 当前解决置信度：<0–89%；P0 填“未评估（紧急升级）”>；依据：<尚不足以自主停止的关键原因>
```

到达此步骤即表示现有资料不足以高置信解决问题，无需再要求用户判断是否已解决。结尾只请求确认是否升级；P0 额外展示事故影响，并提示其应已影响在线业务、事后需事故通报、请慎重提单。只有用户明确回复“确认”“继续创建”等肯定表达后才建群；用户表示“已解决”“不用提单”等时必须停止升级。

用户修改确认信息时：

- 修改租户或问题描述：使旧工单 ID 和五项自助排查结果失效，重新执行受影响的租户、区域与分类选择，调用 `flow create` 创建新追踪工单，完成自助排查后重新按分类动作处理。
- 修改区域：保留当前 `oncall_flow_id`，在新区域下重新选择分类；租户开启 `gpt_search` 时使用新区域重跑智能问答，其他仍适用的自助结果继续保留，然后重新按分类动作处理。
- 仅修改分类：保留当前 `oncall_flow_id` 和自助排查结果，更新 `type_action` 及服务端后续处理字段，再按新分类动作处理。
- 改为 P0：补齐事故影响并跳过五项自助排查；从 P0 改为 P1/P2：使用当前追踪工单补做五项排查。
- 更新后重新展示完整确认信息并等待明确确认。

## 8. 最后一步：发起群聊

```bash
bytedcli oncall chat create \
  --flow-id <oncall_flow_id> \
  --tenant-id <tenant_id> \
  --message "<trigger_message>" \
  --priority <P0|P1|P2> \
  --region "<region>" \
  --question-type-id <question_type_id> \
  --confirm \
  --format table
```

P0 追加 `--urgent-description "<urgent_description>"`。

`--confirm` 只能在用户已经明确同意升级后携带。成功后只展示实际返回且用户需要的信息：工单 ID、租户、分类、等级、区域和下一步；处理人、创建时间和群链接仅在返回非空时追加。返回 `open_chat_id` 时使用命令生成的飞书群聊链接。只有 `chat create` 成功后才能表述为“已发起 Oncall”。
