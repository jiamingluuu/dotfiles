# Vimo overseas routing

Read this reference only for CapCut overseas Vimo Web requests. The CLI surface is flat, but
overseas services, sessions, and business objects remain separate from CN.

## Domain selection

```bash
bytedcli --site i18n vimo creator list [options]
bytedcli --site i18n vimo user list [options]
bytedcli --site i18n vimo template list [options]
bytedcli --site i18n vimo template tab list [options]
bytedcli --site i18n vimo incentive activity list [options]
```

- Route 创作者/作者/creator requests to `vimo creator`.
- Route 用户查询/基础用户视图/CapCut UID or CapCut ID requests to `vimo user`.
- Route template-management resources and navigation Tabs to `vimo template`.
- Route operation activities, user-incentive activities, and recommended templates to
  `vimo incentive`.

A UID alone does not make a user-query record a creator. Use the requested page/object and action.

## Authentication and network

Overseas `/user/**` reads first use the appropriate personal ByteCloud JWT where supported, then
fall back after HTTP 401 according to the documented Vimo Cookie/session policy. Other overseas
Vimo Web commands use the same overseas session boundary. Never reuse a CN Vimo Cookie or CN JWT
as an overseas browser session.

For office-network TikTok SSO/CAS login, the authentication command still uses its concrete auth
site:

```bash
bytedcli --site i18n-tt auth login --session --auto --yes
```

Vimo business commands remain canonical under `--site i18n`.

Managed runtimes may inject the complete browser `Cookie` header value through
`BYTEDCLI_VIMO_COOKIE`. Pass only the value without a `Cookie:` prefix. The value is process-scoped,
host-bound, not persisted, and must never be printed. A rejected injected snapshot does not fall
back to another local identity. Same-origin `Set-Cookie` updates affect only the current process.

`BYTEDCLI_NETWORK_PROFILE=prod` selects the production-network Vimo origin. Production-network
access requires an injected Cookie and fails closed without one; it does not attempt office-network
SSO/CAS. Protected PPE routing headers are ignored on that origin.

```bash
printf 'Vimo Cookie: '
IFS= read -rs BYTEDCLI_VIMO_COOKIE
printf '\n'
export BYTEDCLI_VIMO_COOKIE
bytedcli --site i18n --json vimo creator list --page-size 1
BYTEDCLI_NETWORK_PROFILE=prod bytedcli --site i18n --json vimo template list --page-size 1
unset BYTEDCLI_VIMO_COOKIE
```
