# DevFlow 机房（Region → 数据中心）基础知识

本引用文档提供 DevFlow 机房（`dc` / `dc_list`）与地域分区（zone / region）的对应关系，用于**理解用户口语里的机房分区说法**（例如「华北」「华东」），把它翻译成后端使用的机房代码（DC code）。

## 何时使用

- 用户用「华北」「华北6」「华东」等中文分区名描述目标机房，需要知道它对应哪些 DC 代码时
- 需要向用户解释某个 DC 代码属于哪个分区时
- 加泳道（`develop-lane add`）、改泳道机房（`develop-lane-dc update`）时用户给的是分区名而不是具体 DC

## Region → 数据中心对照

当前已知的分区映射如下：

| 分区（zone） | 中文名 | 包含的机房（DC code） |
| --- | --- | --- |
| China-North | 华北 | `LF`、`LQ`、`HL`、`GL` |
| China-North6 | 华北6 | `XH`、`ZB`、`GL2` |
| China-East | 华东 | `HJ`、`ZJG`、`JJ` |

CN 控制面 PPE 泳道当前已知的机房候选全集为：`LF`、`LQ`、`HL`、`GL`、`XH`、`ZB`、`GL2`、`HJ`、`ZJG`、`JJ`。

## 使用原则

- 本文档只是**翻译辅助**：把用户口语的分区名映射到候选 DC 代码，不改变各能力文档里「机房参数会造成实际部署影响」的既有约束
- **严禁 AI 仅凭本映射自动决定并填写 `dc_list`**。当用户只说了分区（如「华北」）而没有点名具体机房时：
  - 一个分区通常包含多个 DC，AI 不得替用户从中挑一个
  - 正确做法是留空 `dc_list` 调用一次，把后端返回的候选机房列表原样展示给用户，让用户在候选中确认；本映射仅用于帮助用户/AI 读懂候选列表里的 DC 代码分别属于哪个分区
- 用户若已明确点名具体 DC（如 `LF`），将机房代码统一为大写后传递，不需要再借助本映射
- 上表是当前已知的静态基础知识，可能随平台调整而变化；**以后端返回的候选机房列表为准**，本表与后端不一致时以后端为准
- `region`（`cn` / `i18n`，控制面）与这里的 zone（机房分区）不是同一层概念，不要混淆：机房分区是在 `cn` 控制面下进一步细分的物理机房

## 备注

- 机房是 `region`（区域）维度的，与泳道名无关，不要根据泳道名推断机房
- 相关能力文档：加泳道 `add-develop-lane.md`、改泳道机房 `update-develop-lane-dc.md`
- 如果在完成本 skill 任务过程中需要使用其他 skill，必须使用名称带有 `bytedance-devflow-` 前缀的 skill
