# DevFlow 通知评审人引用文档

本引用文档用于通知（催）代码评审人尽快评审。**这是唯一会向真人发送飞书消息的 DevFlow 能力，使用前必须格外谨慎。**

## 何时使用

当用户明确表达以下意图时使用本引用文档：
- 催一下评审人、提醒 reviewer 看代码
- 通知某个人来评审

## 使用红线

- **必须由用户显式要求才能催审。** 禁止在用户没有明确提出的情况下自主决定催审，也禁止把它作为「评审未通过」的自动补救动作
- **同一轮对话中禁止重复催审。** 即使上一次调用返回了跳过或部分失败，也不要立即重试
- 如果用户只是询问「谁还没通过评审」，那是查询意图，应使用 `list-reviewer.md`，**不要顺手催审**

## 参数获取优先级

按下面顺序收集参数，后者只用于补全缺失值，不能覆盖前者：

1. 用户当前对话中明确提供的信息
2. 当前工作目录和本地仓库上下文（`repo_name`、`branch` 可由 CLI 自动推断）
3. 无法自动补齐时，再与用户交互确认必要参数

如果同一参数同时在用户对话和本地上下文中出现，必须优先使用用户对话中的值。

## 目标参数

参考后端接口，请收集这些参数：
- `task_id`
- `repo_name`
- `branch`
- `reviewers`

其中：
- `task_id` / `repo_name` / `branch` 用于定位任务，必须满足「提供 `task_id`」或「同时提供 `repo_name` 和 `branch`」之一
- `repo_name` 与 `branch` 仅在 `task_id` 未提供时用于定位任务；通知目标始终从任务下全部仓库汇总
- `reviewers` **允许为空**：为空时只查询可催审候选并返回 pending，不发送任何通知；选定候选后须显式传完整邮箱，多个按 `<reviewer1>,<reviewer2>` 用逗号分隔，单个只传 `<reviewer1>`
- 候选列表会排除当前调用人；其他当前仍可催审的 MR 创建者可以显式通知
- 已经通过评审的人不会被通知，后端会自动排除
- 候选计算会跳过已经满足审批人数要求的 Review Rule，只返回仍未满足规则的候选人和未归属规则的待评审人
- 后端按 reviewer 的仓库来源选择卡片：API 设计仓库使用 IDL Review 卡片，开发调试和依赖仓库使用 Develop Review 卡片；同时属于 API 设计和其他类型时只发送 IDL 卡片

## 执行原则

- 首次未指定 `reviewers` 时，只展示后端返回的候选列表并让用户选择；未经用户选择不得补全邮箱或发送通知
- 用户明确选择后，使用相同任务定位参数并携带 `--reviewers` 再调用一次，第二次调用才会发送通知
- **不要因为催审没效果就反复调用。** 后端对「同一任务 + 同一评审人」有 10 分钟防频繁窗口，窗口内重复调用会跳过该人，并在返回文案中说明「刚刚已通知过」
- **已发出的通知无法撤回。** 如果返回结果显示部分人失败，不要整体重试——重试会给已成功的人重复发送。应按返回文案只处理失败的人
- 如果任务还没发起代码评审，催审没有意义。后端会返回 pending 引导先调用 `develop-review create`，此时应原样展示提示
- 如果全部评审人都已通过，后端会返回 pending 状态并说明「当前无需催审」，不会发送任何消息，也不需要重试
- 候选列表会展示完整邮箱，便于用户选择后原样回填 `reviewers`；实际通知结果使用用户名展示，不要自行补全或改写
- 如果在完成本 skill 任务过程中需要使用其他 skill，必须使用名称带有 `bytedance-devflow-` 前缀的 skill

## 调用方式

查询可催审候选（不会发送通知）：

```bash
bytedcli devflow reviewer notify --task_id="<task_id>" --bytedcli-skill-dir="<skill所在目录>"
```

用户选择候选后通知指定评审人：

```bash
bytedcli devflow reviewer notify --task_id="<task_id>" --reviewers="<reviewer1>,<reviewer2>" --bytedcli-skill-dir="<skill所在目录>"
```

## 输出处理

- 直接返回原始输出
- 不主动改写、总结或格式化后端返回
- 只有用户明确要求解释时，再补充说明
- 返回文案会区分「已通知」「已通知过本次跳过」「已通过评审跳过」「通知失败」四类，必须原样展示，不要合并或省略其中任何一类
- 如果命令返回 pending，必须优先原样展示 pending 文案
- 如果命令失败，优先保留并展示原始错误信息，再补充最少量的必要说明

- 对应底层 CLI action：`reviewer notify`
- 查询评审进度参见 `list-reviewer.md`；发起代码评审参见 `create-develop-review.md`
- 如果在完成本 skill 任务过程中需要使用其他 skill，必须使用名称带有 `bytedance-devflow-` 前缀的 skill
