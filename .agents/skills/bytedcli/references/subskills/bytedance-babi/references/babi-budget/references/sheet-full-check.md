# 预算填报表格全量校验

本流程用于校验用户提供的飞书商品填报表格。开始前已按产品技能完成 `bytedcli babi` 的安装、版本门禁和认证；本流程额外依赖 `lark-cli`。

## 固定执行顺序

1. 用户必须提供待校验的飞书表格链接。链接缺失时只请求该链接，不能猜测文档。
2. 使用已有的 `lark-cli` 飞书能力；不要安装、升级或配置该 CLI。
3. 先通过 `lark-cli` 获取该表格的文档标题；读取当前安装版本的 `lark-cli --help` 确认标题读取、表格导出和单元格写入命令及参数，禁止猜测其子命令。
4. 标题完全匹配 `商品填报模板增量_<预算单据ID>_<填报口径>_...` 时，以 `_` 分割：
   - 第 2 段（数组下标 `1`）为 `budget-instance-id`。
   - 第 3 段（数组下标 `2`）为 `data-caliber`，仅接受 `0`（增量）或 `1`（全量）。
   - `budget-data-type` 固定为 `1`（商品按量）。
   - `update-type` 固定为 `1`（覆盖所有数据）。
5. 标题不符合上述格式、分段不足，或第 3 段不是 `0`/`1` 时，不得从标题推断参数。要求用户额外确认预算单据 ID 和填报口径；填报方式仍默认商品按量，更新类型仍默认覆盖所有数据，并在最终汇总中明确这些默认值。
6. 用 `lark-cli` 导出表格的**带行号标注 CSV JSON 产物**到本地。产物必须包含非空 `annotated_csv`，每条记录的首字段以 `[row=N]` 开头，首列表头可能为 `错误信息`；同时保留 `current_region` 和列字母映射（如 `col_indices`）。普通裸 CSV 不能直接传给 `bytedcli babi`。
7. 从导出产物读取 `current_region`，再执行：

## 参数枚举

1. budget-data-type：1=商品按量填保，2=打包金额填报，3=火山金额填报，4=商品按量批量模板，5=打包金额批量模板"
2. update-type：1=覆盖全部数据，2=更新指定数据"
3. data-caliber：0=增量，1=全量"

```bash
bytedcli babi budget sheet full-check \
  --budget-instance-id '<budget-instance-id>' \
  --budget-data-type 1 \
  --update-type 1 \
  --data-caliber '<0-or-1>' \
  --annotated-csv '<lark-cli-export.json>' \
  --current-region '<current-region>' \
  --format json
```

不要省略 `--current-region`，即使当前 CLI 在请求前会从请求体移除它；该参数是命令输入契约的一部分。

## 响应判定与回写

先判定命令是否发生调用失败（认证、权限、网络、参数格式等）。调用失败时原样说明错误，并保留 `logId`、`RequestId` 或其他追踪字段；不要写回表格。

命令成功后按如下优先级处理 JSON 响应：

1. `TopLevelErrMsg`（或后端返回的等价 snake_case 字段）非空，说明整体业务错误。将该错误直接返回给用户，不写入逐行错误。
2. `check_res_map` / `CheckResMap` 有失败项时，CLI 已过滤掉 `pass=true` 的行，只处理剩余项目。键是实际飞书行号，必须直接使用该行号，不得根据数据行序号重新计算。
3. `check_res_map` / `CheckResMap` 有失败项时，先向用户返回失败行数、拟写入的行号与字段范围；只有用户明确授权本次回写后，才把逐行错误的 `failed_msg` / `FailedMsg` 写入原表格的 `错误信息` 列：
   - 原表存在该列时更新该行该列；不存在时在第一列插入名为 `错误信息` 的列，再写入错误。
   - 先使用导出 CSV 的表头、`col_indices` 和该行值定位错误消息提到的字段；仅高亮能明确匹配的字段所在单元格，背景色设为红色，同时将对应hang 的错误信息列对应的表格标为浅红色。字段映射里的报错信息中，计费项是一个集合的概念，代表商品、组合计费单元和售卖区域有一个有问题，具体是哪个有问题往往会在后面表示，不能将计费项有问题直接认为是组合计费单元有问题
   - 消息包含精确表头、商品 ID、计费项、区域或月份等值时，优先匹配对应表头/值；有多个候选或无法确定字段时，只写错误信息，不得猜测并误标红单元格。
   - 保持其他单元格、公式、格式及历史错误信息不被覆盖；回写后读取或使用 lark-cli 的成功结果确认写入完成。
4. `TopLevelErrMsg` 为空且失败行映射为空（或不存在）时，向用户返回“校验通过”；不要新增错误列、不要改变单元格背景色。

## 最终汇总模板

调用脚本拿到校验结果后，向用户给出校验结论：是整体错误还是逐行错误数量还是或“校验通过”。不要在汇总中暴露认证令牌、完整本地导出内容或无关表格数据。同时将请求前的参数展示给用户，以便于确认本次校验口径是否符合预期：
参数1 | 预算单据 ID | 标题第 2 段，或用户确认值 |
参数2 | 填报方式 | 商品按量（`budget-data-type=1`） |
参数3 | 更新类型 | 覆盖所有数据（`update-type=1`） |
参数4 | 填报口径 | 标题第 3 段，或用户确认值；`0=增量`、`1=全量` |
