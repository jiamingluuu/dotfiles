# 预实偏差分析报告

本流程用于用户通过 Agent 调用 `bytedcli babi` 生成预算单元的预实偏差分析报告。报告必须基于真实返回数据，不能使用 mock、静态样例或基于名称猜测的 ID。

## 触发与输入

以下表达及其明确同义词均触发本流程：

- 预实分析
- 预实消耗
- 预实偏差分析
- 预算执行分析
- 分析某预算单元的预算与实际差异

预算单元是唯一必须由用户提供的业务参数。用户未提供时，只追问预算单元名称或稳定 ID，不要求用户补齐 CLI 参数。

默认值：

- 预算区域：`cn`；用户明确指定海外时使用 `oversea`。
- 账期：默认展示当年 1 月至当前月。用户可手动调整账期范围，但最大跨度不超过 18 个月。
- 预算版本：查询对应预算区域的版本列表，取接口按时间倒序返回的第一项。
- 金额口径：`status=1`，即纯资源。
- 币种：沿用接口返回值，不自行换算。
- 报告形态：预实分析默认生成飞书文档和交互式 HTML dashboard；用户明确指定其他形态时按其要求调整。HTML 优先交付用户可取得的本地 `index.html` 与必要的 `data/` 文件（可打包下载），不要求部署。Agent 可依据自身环境和本次授权，额外提供字节办公网可访问的链接，方便用户查看效果；链接是可选能力，没有链接不影响本地 HTML 报告交付完成。

## 预算单元确认

使用 [babi-budget 指南](../../babi-budget/GUIDE.md) skill 完成预算单元解析和预算查询。

1. 用户提供稳定预算单元 ID 时直接使用，不再按名称搜索。
2. 用户只提供名称时，在已确定的预算区域执行预算单元搜索。
3. 只有一个类型明确且名称精确匹配的候选时继续。
4. 出现模糊匹配、重名或多个候选时，必须展示以下信息并等待用户二次确认：
   - 预算区域
   - `budget_source_id`
   - `budget_source_name`
   - `category_type`
   - `group_key`
   - `upper_source_id`
5. 候选过多时要求用户补充更完整名称；没有候选时要求用户核对名称或预算区域。
6. 收到确认前禁止查询报告数据，禁止按排序、相似度或历史经验选择第一项。

## 时间与版本

### 默认账期与可选跨度

默认账期为当前时区下的当年 1 月至当前月：

- `BeginMonth`：当年 1 月月初，毫秒时间戳。
- `EndMonth`：当前月月初，毫秒时间戳。
- 默认月份区间前闭后闭，覆盖当年累计至当前月。

例如当前月为 2026-08，则默认报告账期为 2026-01 至 2026-08。

用户可手动调整账期范围，但必须满足：

- 起止月份都在可选月份列表内。
- 月份跨度最大不超过 18 个月。
- 超出 18 个月时，页面与 Agent 都必须拦截，并明确提示用户重新选择结束月份。

### 最新预算版本

1. 在对应预算区域查询预算版本列表。
2. 接口结果按时间倒序时，取第一项作为默认版本。
3. 在报告"查询口径"中明确写出实际使用的预算版本。
4. 用户指定版本时优先使用用户版本，但应先校验它存在于版本列表。
5. 版本列表为空、指定版本不存在或查询失败时停止生成，不得按年份、月份或历史经验猜版本。

## 数据查询链路

预算单元确认后，按同一 `BudgetArea`、`BudgetVersion`、`BeginMonth`、`EndMonth`、`BudgetSourceIds` 和 `Status` 执行查询：

1. 使用 [babi-budget 指南](../../babi-budget/GUIDE.md) skill 查询预实消耗概览，取得预算单元按月的成本账单、成本预算和成本预算执行率等指标。
2. 按报告覆盖的每个月分别查询成本消耗概览，取得 `BillAmount`、`BudgetAmount`、`ConsumptionRate`、`Currency`、`Status`、`TimeRate`。顶部 KPI 指标卡、整体概览及 `trend` 的月度账单/预算必须直接使用该接口逐月返回值，以确保与 BABI 页面同口径；禁止使用成本明细、`tableRows` 或 `productRows` 求和替代概览口径。
3. 查询成本 Top 商品，取得账单和预算两个口径的 Top 商品。
4. 查询成本消耗明细，至少保留以下聚合维度：
   - `CustomerBudgetSourceId`：返回字段"需求方预算单元"，作为子预算单元。
   - `BudgetDepartmentId`：返回字段“1级供给方”，写入页面数据字段 `providerLevel1`。
   - `BudgetSourceId`：商品预算单元。
   - `Product`：商品。
   - `Flavor`：组合计费单元。
   - `Region`：售卖区域。
   - `Period`、`BillType`、`BudgetCategoryType`：填报、计费与供给方分类口径。
5. 概览或明细支持分页时，持续翻页直到达到返回总数或当前页为空；不得只用第一页生成"全量"结论。
6. **CD 为默认必查链路**，不得因用户未单独提及而跳过；映射读取须遵守下文“CostDriver 口径”的用户权限前置条件：先按“CostDriver 口径”读取映射文档，取得核心 CD 与 CD 所属预算单元；再执行 `budget cost-driver search` 获取 `CD_ID:BUDGET_SOURCE_ID` 级联；最后执行 `budget cost-driver actual-budget list` 查询月度 `forecast_count`、`actual_count` 和 `actual_execution_rate`。不得使用 [babi-bill 指南](../../babi-bill/GUIDE.md) 的账单字段替代 CD 执行率。

可并行的只读查询应并行执行；预算单元确认和版本确认是前置步骤，不能与后续数据查询并行。

## 指标计算

设月份为 `m`：

- `A_m`：该月实际账单金额。
- `B_m`：该月预算金额。
- `T_m`：时间进度。历史月固定为 `1`；当前月优先使用成本概览返回的 `TimeRate`。若返回值缺失或非法，按"当前日期所在日 / 当前月总天数"计算并在报告中说明回退口径。

### 月度指标

- 历史月消耗率：`A_m / B_m × 100%`。
- 当前月消耗进度：`(A_m / B_m) / T_m × 100%`。
- 历史月超支金额：`A_m - B_m`。
- 当前月超支金额：`A_m - B_m × T_m`。

当 `B_m = 0` 时：

- `A_m > 0`：标记"有账单无预算"，不计算无限大的消耗进度。
- `A_m = 0`：标记"无预算且无账单"。

### 负预算处理（关键）

预算金额 `B_m` 可能因预算口径调整、冲销或重编出现负值。负预算会导致"超支金额 > 总成本"的反直觉展示（如总成本 184 万但超支 1406 万）。处理规则：

- 用于超支金额和消耗进度计算时，负预算按 `0` 处理：`B_m' = max(B_m, 0)`。
- 用于"区间预算"展示时，负值也按 `0` 处理，并在报告中注明"含预算冲销调整"。
- 每个商品行和子预算单元行的月度预算映射（`budgetByMonth`）中，负值同样按 `0` 处理。
- 负预算修复后需要重新计算超支金额（`overspendAmount`）和消耗进度，确保 Top 商品和 Top 子预算单元列表正确。

### 12 个月汇总指标

- 实际账单：`Σ A_m`。
- 有效预算：`Σ(B_m × T_m)`；历史月 `T_m=1`，当前月使用当前时间进度。
- 整体消耗进度：`ΣA_m / Σ(B_m × T_m) × 100%`。
- 累计超支金额：`Σ max(A_m - B_m × T_m, 0)`；负值不冲抵其他月份的超支。

### 异常判断

- 历史月异常（不含当前月）：消耗进度大于 `100%`，并且消耗进度严格大于关联子预算单元当月的 CD 执行率。
- 当前月异常：由于当前月无法稳定获取 CD 执行率，仍仅按消耗进度大于 `100%` 判断。
- 历史月缺少有效 CD 执行率时，异常判断降级为仅比较消耗进度：消耗进度大于 `100%` 即判定为异常；不得以 `0` 或其他 CD 代替缺失值。
- 子预算单元区间异常：所选账期内至少一个月份满足上述对应月份口径，并列出全部"异常月份"。
- 商品异常：先按商品汇总当月账单与预算；存在有效 CD 执行率时，要求消耗进度大于 `100%` 且严格大于 CD 执行率；确实无法取得 CD 执行率时，仅按消耗进度大于 `100%` 判断异常。
- Top 商品：只在正向超支商品中按累计超支金额降序，不按账单金额或账单占比替代。
- 数据缺失、脱敏或权限受限：标记"未确认/无数据"，不能转成数值 `0`。

## CostDriver 口径

映射读取遵守 [Cost Driver 预实分析](../../babi-budget/references/cost-driver.md) 的当前用户权限边界。
该前置条件优先于下文的必查链路：映射不可访问时，停止依赖该映射的 CD 查询，保留 CD 章节并说明
“CD 映射不可访问”；继续当前用户已有权限的成本、预算和其他独立部分。为受影响子单元记录
`mappingStatus=inaccessible`、`queryStatus=not_applicable` 和 `reason`，有请求标识时保留
`requestId/logId`。不得写为 `unmapped`，不得从其他身份的缓存或导出内容补齐映射与派生数据。

保留现有 HTML 模板，不要求页面新增权限状态。存在 `mappingStatus=inaccessible` 时，在报告正文的
CD 章节、数据质量与限制以及最终交付说明中明确写出“CD 映射不可访问”及受影响范围。现有模板
不能区分权限受限与无映射：没有任何已核验映射时仍可能显示“没有建立映射关系”，该空态不能
作为无映射的证据；须在上述说明中指出这一限制。其他已授权且已核验的 CD 可继续展示，不得
为改变页面空态伪造 `mapped` 状态，也不得把部分报告称为完整 CD 分析。

### 子预算单元逐级映射门禁

CD 查询必须由成本明细中的**全部子预算单元**驱动，不得从顶层预算单元直接推导：

1. 从 `tableRows` / `productRows` 提取全部唯一子预算单元 ID 与名称，作为待核查全集。
2. 对全集逐个读取人工映射表，按子预算单元 ID 优先、名称兼容的顺序匹配 `核心CD` 与 `CD所属预算单元`；禁止只在映射表中搜索顶层预算单元名称后直接结束。
3. 对每条映射，用 `budget cost-driver search` 将人工 CD 名称解析为系统真实 CD；名称不完全一致时必须完成候选核验，不得因精确搜索为空直接标记无映射。
4. 在 `search` 结果中定位映射表指定的 `CD所属预算单元`，使用 `CD_ID:CD所属预算单元ID` 调用 `actual-budget list`。禁止使用顶层预算单元 ID 或子预算单元自身 ID替代该 ID。
5. 每个子预算单元都写入一条 `cdQueryAudit`。只有全集逐条成功读取并核查且全部为 `mappingStatus=unmapped` 时，才允许在报告中判定“没有建立映射关系”。顶层预算单元查询为空不构成无映射证据。

`cdQueryAudit` 的每条记录必须包含 `mappingLookupScope=sub_unit` 与 `mappingSource`，以证明映射是按子预算单元逐条核查而不是顶层直查；已映射记录还必须包含系统 CD 名称、`CD所属预算单元` 和最终 `costDriverPair`。

1. CD 名称必须来自已核验映射：部分预算单元及其子预算单元的核心 CD 维护在飞书文档《抖音预算单元和CD的映射关系》（https://bytedance.larkoffice.com/wiki/R4EwwRENXiTuARkHZCXcqB0MnBc）中，`budget cost-driver search` 的下拉级联不覆盖这类子单元。生成 CD 章节前，必须先按 [babi-budget 指南](../../babi-budget/GUIDE.md) skill 的 [Cost Driver 预实分析](../../babi-budget/references/cost-driver.md) 读取该映射文档，取得每个子预算单元的 `核心CD` 与 `CD所属预算单元`（该 CD 数值应查询的业务口径预算单元），据此构造 `--cost-drivers` 级联对；映射缺失或标记为空时标注"未确认/无数据"，不能用"用户使用时长"等默认名称填补缺失映射。
2. 预算 CD、实际 CD 和 CD 执行率来自 CostDriver 预实数据源：确定核心 CD 后，用 `bytedcli babi budget cost-driver actual-budget list`（`forecast_count` 预测 CD、`actual_count` 实际 CD、`actual_execution_rate` CD 执行率）查询真实月度序列，`--cost-drivers` 使用 `search` 返回的级联对。不能仅用本页面账单金额反推或伪造预算 CD。
3. CostDriver 数据能力需拆分判断；只有具备映射读取权限时才继续查询，并记录证据：
   - 已确定核心 CD 且 `actual-budget list` 返回预测/实际/执行率序列时，据此生成 CD 趋势与执行率。
   - 已获取 CD 名称，但级联查询返回空或失败时，页面与明细表保留 `CD名称` 并标注“未确认/无数据”，同时在 `cdQueryAudit` 记录 `queryStatus` 及 `requestId` / `logId`；不得补 mock 或默认值。
   - 映射文档未覆盖该单元时，标注“CD 映射未确认”，并在 `cdQueryAudit` 记录 `mappingStatus=unmapped` 与原因，继续生成其他已具备证据的部分。
4. CD 趋势以 12 个月窗口内第一个同时具有预算 CD 和实际 CD 的月份为默认基准月：
   - 预算 CD 增幅：`(当月预算 CD - 基准月预算 CD) / 基准月预算 CD × 100%`。
   - 实际 CD 增幅：`(当月实际 CD - 基准月实际 CD) / 基准月实际 CD × 100%`。
   - CD 执行率趋势：直接展示各月执行率，不相对基准月换算。
5. 基准月值为 `0` 或缺失时，不计算增幅并标注原因。
6. 当前月 CD 执行率 `>100%` 标记风险；历史月 `<100%` 标记未达预算，`>=100%` 标记超预算或需关注。
7. CD 数据脱敏：页面和报告中不输出 CD 原始绝对值，只展示增幅（%）和执行率（%）。CD 名称可用真实名称，但 `cost_driver_value` 绝对值不展示。

## 报告结构

报告按以下顺序生成：

1. **查询口径**
   - 预算单元名称与稳定 ID
   - 预算区域、预算版本、金额口径、币种
   - 12 个月账期、报告生成时间、当前月时间进度
2. **核心结论**
   - 整体消耗进度、累计超支金额
   - 异常子预算单元数量与超支月份
   - 超支金额最高的商品
   - 数据质量或能力缺口
3. **整体预实概览**
   - 12 个月实际账单、有效预算、整体消耗进度、累计超支金额
4. **月度趋势**
   - 每月实际账单、预算、超支金额、消耗进度
5. **高风险子预算单元**
   - 子预算单元、异常月份、账单、预算、超支金额、消耗进度
   - 按最高消耗进度或累计超支金额降序，并写明排序口径
6. **超支 Top 成本商品**
   - 商品、账单、预算、超支金额、异常月份
   - 按累计正向超支金额降序
7. **分析明细**
   - 预算单元、子预算单元、商品预算单元、商品、Flavor、Region
   - 12 个月逐月账单、预算、超支金额和消耗进度
8. **CostDriver 分析**
   - CD 名称、预算 CD 增幅、实际 CD 增幅、CD 执行率趋势
   - CostDriver Tab 在存在关联 CD 时固定展示提示：“以下CD是人工建立的映射关系，如需增加CD请联系@李枞。”
   - 当当前预算单元下所有子预算单元均未建立 CD 映射（`cdQueryAudit` 全部为 `mappingStatus=unmapped`）时，CostDriver Tab 隐藏指标卡片、筛选控件和空白图表，在整个 Tab 内容区展示：“暂无数据。当前预算单元没有和CD建立映射关系，如需分析CD请联系@李枞。”
   - 存在 `mappingStatus=inaccessible` 时，按“CostDriver 口径”在报告正文和最终交付说明中披露权限与模板限制，保留原 HTML 模板。
   - 能力不足或映射缺失时保留章节并明确说明，不得填 mock
9. **数据质量与限制**
   - 空值、脱敏、权限、分页、月份缺口、映射缺口
   - 关键请求的 `logId` / `RequestId`（如返回）

结论必须区分"事实"和"推测"。聚合数据只能证明发生了超支或趋势变化，不能直接证明具体根因。用户继续追问"为什么超支""成本为什么变化"时，再进入完整成本归因链路，并下钻到具体事件及相关证明链接。

## HTML 报告页面生成

当用户发起预实分析任务时，除飞书文档外，**必须同时生成一个交互式 HTML 报告页面**（HTML dashboard 是默认必产交付物，不是可选项）。HTML 报告页面必须复用固定的预算预实 dashboard 模板，不得临时更换页面框架、回退到原型样例页，或让模型自由设计与当前定型版本不一致的新交互。

### 模板定位

模板随完整 FinOps Skill 或宿主内置的完整 FinOps 指南分发。将实际加载的 `SKILL.md`
（独立 Skill）或 `GUIDE.md`（宿主完整指南）所在目录记为 `<finops_guide_dir>`，
模板在它的 `templates/budget-dashboard/` 子目录，不要相对 shell 当前目录查找模板。
模板版本和维护方式见同目录模板的 `README.md`。本包包含模板，不包含宿主部署工具。

### 生成流程

1. **准备模板目录**：预算单元确认后，创建本次报告输出子目录，并从 `<finops_guide_dir>/templates/budget-dashboard/` 复制 `index.html` 和 `data/` 目录。模板目录中的 `data/demo_mock_prototype.json` 只用于理解结构和本地预览，正式报告不得把它作为数据源、默认加载文件或交付链接。

   ```bash
   mkdir -p "<report_output_dir>"
   cp -R "<finops_guide_dir>/templates/budget-dashboard/." "<report_output_dir>/"
   rm -f "<report_output_dir>/data/demo_mock_prototype.json"
   ```

### 页面标准模板与交互规范

页面固定为单文件 HTML（复制自 `templates/budget-dashboard/index.html`），使用 ECharts 渲染图表，内联 CSS 和 JS。除非用户明确要求另一套页面形态，否则所有预实分析页面都必须遵循以下标准模板：

#### 1. 顶部查询区

- 预算大区、预算单元、账期区间、预算版本、金额口径使用固定顶部查询区。
- 预算单元唯一且已确定时，页面默认直接展示当前预算单元；不得默认落回抖音、懂车帝或任何历史样例对象。
- 本次任务包含多个预算单元时，顶部预算单元筛选框必须列出全部已确认单元，支持单选切换和多选聚合；这些单元共用同一个 dashboard，不得拆成多个页面。
- 用户查什么预算单元，页面打开后就直接展示什么预算单元。

#### 2. Tab 与概览区

- 保留 `预实概览 / CostDriver 分析` 两个 Tab。
- 保留异常告警 Banner、KPI 指标卡片、核心结论区、子预算单元卡片等既有信息架构。
- 这些模块的数据必须来自真实 JSON，不得使用示例文案或静态样例 chips。

#### 3. 分析维度

分析维度固定支持以下选项，并按用户选择顺序决定聚合顺序：

- 预算单元
- 子预算单元
- 1级供给方
- 供给方商品
- 组合计费单元
- 售卖区域

额外规则：

- **移除“分析标签”维度**。页面中不得再展示“分析标签”作为分析维度选项。
- “1级供给方”固定排列在“子预算单元”和“供给方商品”之间，取成本明细接口 `BudgetDepartmentId` 对应的输出字段“1级供给方”，写入 `productRows.providerLevel1`。
- 当分析维度包含“1级供给方”时，趋势图和明细表必须切换到 `productRows`，按 `providerLevel1` 真实聚合；字段缺失时展示“未确认/无数据”，不得沿用商品或预算单元名称替代。
- 当分析维度包含“供给方商品”时，趋势图和明细表必须基于 `productRows` 真实展开，而不是继续复用子预算单元聚合后的 `tableRows`。
- 当分析维度包含“组合计费单元”或“售卖区域”时，也必须继续基于 `productRows` 的真实粒度字段展开，不能只显示空行或沿用上一级聚合结果。
- 当分析维度包含多个层级时，趋势图图例、明细表行和聚合逻辑都必须按当前维度及顺序真实重算，不得只改表头不改数据。

#### 4. 筛选框

页面筛选区至少保留以下筛选项：

- 子预算单元
- 1级供给方
- 供给方商品
- 组合计费单元
- 售卖区域
- 数值筛选条件组

筛选规则固定如下：

- **筛选区不得重复提供预算单元筛选项**；预算单元完全由顶部预算单元选择器控制。
- 顶部预算单元变化后，子预算单元、1级供给方、商品、组合计费单元和售卖区域候选必须基于当前已选预算单元的数据集重新生成，禁止残留其他预算单元选项。
- 子预算单元、1级供给方、供给方商品、组合计费单元、售卖区域统一使用下拉复选框，均支持搜索、勾选全部、部分多选和清空；清空等于全选/不过滤。
- “1级供给方”筛选项固定显示在“子预算单元”和“供给方商品”之间，默认全部选中（即不过滤）；选中部分供给方后，页面必须切换到 `productRows` 并按 `providerLevel1` 真实过滤。
- 下拉复选框展开后允许连续勾选多个对象，勾选过程中面板保持展开且不触发查询；点击面板外、失焦、再次点击触发器或按 Esc 关闭面板时，才统一触发一次查询刷新。
- **移除“分析标签”筛选项**。
- `1级供给方 / 供给方商品 / 组合计费单元 / 售卖区域` 的枚举值都必须来自当前查询对象 `reportData.productRows` 的全量真实数据去重结果，不能只取 Top 商品、异常商品或第一页明细。
- 四个商品粒度筛选框都必须支持：
  - 搜索
  - 多选
  - 清空筛选
  - 清空等于全选/不过滤
- 如果真实数据中存在 `presto` 等商品，筛选框中必须能搜到；如果真实数据中存在某个 `providerLevel1`，则“1级供给方”筛选框中也必须能搜到；搜不到说明选项来源不全，不能交付。

#### 5. 趋势图

- 趋势图固定支持账单、预算、消耗进度三个视图切换。
- 图例应去掉公共前缀，避免多个系列仅名称后缀不同却展示冗长重复文本。
- 趋势图 tooltip 只保留“消耗进度”，不再同时展示“月度消耗进度”和“消耗率”等易混淆指标。
- 页面上没有实际功能的占位按钮应移除，不能保留无意义的 `⇩ / ↻ / ↗` 等按钮。

#### 6. 明细表

- 明细表月份必须随顶部账期筛选动态变化，不能固定只展示主账期和上月。
- 多月展示时，月份按**由近及远**从左到右排列，最左侧是最近月。
- 表格必须支持横向滚动。
- 左侧维度列必须冻结，横向滚动时不跟随滚动。
- 表格支持分页，分页大小至少提供 `10 / 20 / 50 / 100`。
- 表格列排序支持三态：倒序 → 正序 → 恢复默认。
- 明细表只保留“消耗进度”，不再展示“消耗率”。
- 明细表在表头下第一行固定展示汇总行，汇总范围是当前筛选后的全量结果，不受分页影响：账单、预算、超支金额分别求和；消耗进度按汇总账单、汇总预算及对应月份时间进度重新计算；CD 执行率与 CD 名称不聚合，统一展示 `-`。汇总行不得参与分页和排序，也不得重复计入数据行。
- 明细表始终保留 1 列固定 `CD名称`；该列与子预算单元一一对应，不随其他分析维度重复展开成多列。
- 若 `actual-budget list` 返回月度 CD 执行率，则按顶部账期逐月展开 `CD执行率` 列；只有映射缺失，或接口查询为空/失败且已记录查询证据时，才允许只展示 `CD名称` 和“未确认/无数据”。

#### 7. 缺失值、数字格式与展示兜底

- 页面中禁止出现 `undefined`、空白名称或由字段 key 不匹配导致的空展示。
- 商品名称、子预算单元名称、Flavor、Region 等字段都必须设置兜底值。
- 数据缺失、权限受限、映射缺失统一展示为 `未确认/无数据` 或 `--`，不得转换为 0。
- 单位为“亿元”的金额统一保留 2 位小数；百分比统一保留 2 位小数。
- 其他数字（包括元、万元、数量和计数）统一四舍五入取整，不保留小数位。

#### 8. 滚动冻结

- 顶部查询筛选区使用 sticky 固定；页面向下滚动时持续可见。
- 冻结层级必须高于正文图表、表格表头和下拉内容基础层，且下拉面板不得被正文遮挡。

### 数据文件结构

数据文件（唯一命名文件，如 `{budget_source_id}_{timestamp}_{user_tag}.json`）必须按内置模板示例 `templates/budget-dashboard/data/demo_mock_prototype.json` 的结构生成，并包含以下顶层字段：

- `id`：预算单元 ID。
- `params`：查询参数（预算区域、版本、名称、状态、报告月、时间进度、数据截止日、数据来源标记 `babi-cli-real`）。
- `overview`：概览指标（账单、预算、消耗进度、时间进度、异常计数）；其中账单、预算、消耗进度和时间进度必须由逐月成本概览结果汇总或直接取值，不能由明细行反推。
- `settlement`：日结/月结/合计的按月账单、预算、消耗进度。
- `availableMonths`：12 个月份列表。
- `trend`：月度趋势数组（月份、账单、预算、消耗进度）；每月账单、预算和时间进度必须来自该月 `budget consumption cost overview get` 的真实返回。
- `top4Cards`：Top 4 子预算单元卡片数据（含名称、指标、Top 商品列表）。
- `tableRows`：子预算单元明细行（含按月账单/预算/进度映射）。
- `productRows`：商品明细行，必须至少包含以下字段：
  - `product`
  - `subUnit`
  - `providerLevel1`（来自成本明细接口 `BudgetDepartmentId` / 输出字段“1级供给方”）
  - `flavor`
  - `region`
  - `billByMonth`
  - `budgetByMonth`
  - `overallRateByMonth`
  - `monthlyRateByMonth`
  - `cdName`（如已获取）
  - `cdRateByMonth`（如已获取）
- `alertUnits` / `alertGoods`：异常子预算单元和商品名称列表。
- `overspentProductsTop5` / `topProductBill`：超支 Top5 和账单 Top5 商品。
- `summary`：文本摘要（账单文本、预算文本、进度文本、异常计数文本、Top 商品名称列表）。
- `cdQueryAudit`：CD 查询审计数组，必须覆盖 `tableRows` 和 `productRows` 中每个子预算单元；至少包含 `subUnitId/subUnit`、`mappingLookupScope=sub_unit`、`mappingSource`、`mappingStatus`、`queryStatus`。已映射时还需包含 `costDriverName`、`costDriverSourceBudgetUnit`、`costDriverPair`；查询为空或失败时需记录 `requestId/logId`；未映射或不可访问时需记录 `reason`，状态定义见“CostDriver 口径”。禁止只记录顶层预算单元查询结果。

### 关键数据处理规则

生成数据时必须遵循以下规则：

1. **子预算单元名称多重兜底**：卡片名称取值优先级为 `name || subUnit || subUnitRaw`，防止字段 key 不匹配导致显示 `undefined`。
2. **商品名称空值兜底**：明细行中“商品”字段为空时，优先用“商品预算单元”字段兜底，仍为空时使用“未命名商品”，防止 Top 商品出现空白名称。
3. **负预算按 0 处理**：所有用于超支和进度计算的预算值，负数一律按 `0` 处理。
4. **真实数据来源**：数据文件中 `params.dataSource` 必须标记为 `babi-cli-real`，所有金额来自真实 CLI 返回，不补 mock。
5. **并发隔离命名**：输出文件名必须包含 `budget_source_id + timestamp + user_tag`，禁止继续覆写固定文件名。
6. **CD 脱敏**：CD 原始绝对值（`cost_driver_value`）不在页面输出，只展示增幅和执行率。
7. **商品粒度展开规则**：`productRows` 不能只按商品名聚合，必须保留 `product / subUnit / providerLevel1 / flavor / region` 等页面筛选与维度展开所需的最小粒度；`providerLevel1` 必须来自明细接口 `BudgetDepartmentId` 对应的“1级供给方”字段。
8. **商品层级进度规则**：当页面切换到商品/组合计费单元/售卖区域粒度时，消耗进度必须来自对应行的真实月度映射重算，不能出现整列为空。
9. **筛选项来源规则**：页面筛选项中的商品、组合计费单元、售卖区域，必须从 `productRows` 全量去重生成，不得从 Top 商品、异常商品或卡片数据反推。
10. **分析标签下线**：数据生成和页面展示都不再依赖“分析标签”作为页面分析维度或筛选项；如原始数据中仍包含该字段，可保留在原始 JSON 中但页面不得暴露该维度。
11. **概览口径与明细口径隔离**：`overview`、顶部 KPI 指标卡及 `trend` 按月使用成本概览接口真实返回；`tableRows` / `productRows` 仅用于维度下钻、筛选和明细表。两类数据不得互相替代，避免明细聚合因维度、分页或口径差异导致指标卡与 BABI 页面不一致。
12. **明细汇总行**：汇总行由页面基于当前筛选后的全量明细动态计算，固定放在表头下第一行；金额列求和，消耗进度按汇总值重算，CD 相关列展示 `-`，且不参与分页、排序。

## 已知问题与修复方案

以下是 HTML 报告页面开发过程中遇到并修复的问题，后续修改或新建脚本时必须确保不引入同类问题：

### 问题 1：页面默认展示了历史样例预算单元

- **现象**：用户查询的是某个预算单元，但页面打开后默认仍展示抖音或其他样例对象。
- **根因**：页面顶部预算单元元数据仍指向原型样例，未与当前分析对象联动。
- **修复**：单预算单元分析时，页面必须直接固定展示当前预算单元；不得要求用户手动切换到本次查询对象。

### 问题 2：明细表月份不随顶部账期变化

- **现象**：顶部选择 4~8 月，明细表仍只展示主账期和上月。
- **根因**：表格列仍写死为固定两个月字段，而非使用当前筛选月份动态生成。
- **修复**：明细表月份列根据顶部账期筛选动态构建；多月时按由近及远排列，并支持横向滚动。

### 问题 3：横向滚动后左侧维度列跟着滑走

- **现象**：月份很多时表格可以横向滚动，但维度列也一起移出视野。
- **根因**：维度列未使用 sticky/freeze 方案。
- **修复**：左侧维度列使用冻结样式，横向滚动时始终保持可见。

### 问题 4：增加供给方商品维度后，表格和趋势图没有真实展开

- **现象**：用户新增“供给方商品”维度后，明细条数几乎不变，仍停留在子预算单元粒度。
- **根因**：页面仍基于 `tableRows` 渲染，而不是在商品维度下切到 `productRows`。
- **修复**：当分析维度包含“供给方商品”时，趋势图和明细表必须基于 `productRows` 及其聚合结果生成。

### 问题 5：页面出现 undefined

- **现象**：维度列或卡片名称显示 `undefined`。
- **根因**：页面取值字段与数据文件字段不一致，且缺少兜底值。
- **修复**：子预算单元、商品、Flavor、Region 等字段全部增加多重兜底，页面中禁止出现 `undefined`。

### 问题 6：计费单元、售卖区域没有数据

- **现象**：分析维度中加入“组合计费单元”“售卖区域”后，下方图表和表格仍无数据。
- **根因**：`productRows` 未保留 `flavor` / `region` 粒度字段，或聚合逻辑未读取这些字段。
- **修复**：生成脚本必须在 `productRows` 中保留 `flavor` 和 `region`，页面聚合时按选中维度真实重算。

### 问题 7：筛选框搜不到真实商品，如 presto

- **现象**：供给方商品筛选框中搜不到页面中实际存在的商品。
- **根因**：筛选框选项只来自 Top 商品、异常商品或局部数据，而不是全量商品明细。
- **修复**：商品、组合计费单元、售卖区域筛选框的选项统一从当前预算单元 `productRows` 全量去重生成，并支持搜索、多选、清空=全选。

### 问题 8：图例文本重复且过长

- **现象**：趋势图图例存在公共前缀重复，难以阅读。
- **根因**：图例直接使用完整路径字符串。
- **修复**：图例去除公共前缀，仅保留能区分系列的最小文本。

### 问题 9：表格排序和分页交互不完整

- **现象**：排序只有单向，分页固定 10 条。
- **根因**：交互控件未按最终页面要求实现。
- **修复**：表格排序支持倒序、正序、恢复默认三态；分页大小提供 `10 / 20 / 50 / 100`。

### 问题 10：页面同时展示“月度消耗进度”和“消耗进度”造成混淆

- **现象**：tooltip 和表格中存在多个相近口径指标，用户难以区分。
- **根因**：历史页面同时保留了消耗率、月度消耗进度、整体消耗进度多个口径。
- **修复**：页面统一只保留“消耗进度”，不再展示“消耗率”或其他重复命名指标。

### 问题 11：CD 执行率被误判为不可查询

- **现象**：首次生成报告只有 CD 名称或“未确认/无数据”，再次明确提醒后却能查询到 CD 执行率。
- **根因**：主流程把 CD 查询写成可选项，或错误地停在账单/CD 名称层，没有执行映射读取、级联解析和 `actual-budget list` 完整链路。
- **修复**：CD 是预实报告默认必查项。必须执行“映射文档 → `budget cost-driver search` → `actual-budget list`”，并写入 `cdQueryAudit`；映射不可访问时按“CostDriver 口径”停止依赖查询并披露权限限制；只有已核验映射缺失，或查询为空/失败且记录 `requestId/logId` 时，才允许展示“未确认/无数据”。

### 问题 12：用户无法访问内部沙箱 HTML

- **现象**：Agent 生成了本地 HTML，但用户无法打开所返回的沙箱路径。
- **根因**：内部沙箱路径可能仅 Agent 可见，本地生成不等于发布成功。
- **修复**：优先用宿主文件附件或下载入口交付本地报告；环境支持时按“页面部署”额外提供办公网查看链接。缺少链接不影响本地报告完成，但不得将仅 Agent 可见的沙箱路径伪装成用户可访问文件。

### 问题 13：页面使用了原型静态样例数据

- **现象**：页面展示的数据与实际 babi-cli 查询结果不一致。
- **根因**：页面加载了原型阶段的静态样例 JSON，而非真实 CLI 数据。
- **修复**：从 `bytedcli babi` 拉取真实数据并写入本次唯一数据文件。数据文件中 `params.dataSource` 必须标记为 `babi-cli-real`，页面链接必须通过 `?data=` 指向该文件，不能指向模板 demo。

### 问题 14：CD 数据未脱敏

- **现象**：页面直接展示了 CD 的原始绝对值。
- **根因**：CD 原始绝对值属于敏感数据，不应直接展示。
- **修复**：页面和报告中只展示 CD 增幅（%）和 CD 执行率（%），不输出 `cost_driver_value` 原始绝对值。CD 名称可用真实名称。

### 问题 15：商品层级消耗进度为空

- **现象**：分析维度切到“供给方商品”后，趋势图和明细表中的消耗进度列为空。
- **根因**：商品粒度行未正确读取或重算 `overallRateByMonth / monthlyRateByMonth`。
- **修复**：商品、组合计费单元、售卖区域等下钻粒度都必须基于当前行的真实月度映射重算消耗进度，禁止用空值兜底。

### 问题 16：多用户并发生成时数据文件互相覆盖

- **现象**：不同用户或同一用户多次生成报告时，共用固定数据文件名，导致页面展示的数据被后一次查询覆盖。
- **根因**：数据文件以固定 `{budget_source_id}.json` 命名，缺少时间与用户维度隔离；页面也只能按固定文件名读取。
- **修复**：采用方案 A，每次生成报告都输出 `{budget_source_id}_{timestamp}_{user_tag}.json` 唯一文件，并通过页面 URL 参数 `?data=...` 指定加载目标文件，避免并发覆盖。

### 问题 17：只查顶层预算单元导致 CD 被误判为空

- **现象**：人工映射表中多个子预算单元已关联 CD，但 CostDriver Tab 仍显示“当前报告无 CD 数据”或整页无映射提示。
- **根因**：生成链路只用顶层预算单元 ID 查询 `cost-driver`，没有遍历成本明细中的子预算单元并逐条读取人工映射；顶层查询为空被错误外推为全部子预算单元无映射。
- **修复**：以全部唯一子预算单元为全集，逐个执行“人工映射 → 系统 CD 名称解析 → CD所属预算单元匹配 → `CD_ID:CD所属预算单元ID` 查询”，并为每个子预算单元写入包含 `mappingLookupScope=sub_unit` 和 `mappingSource` 的 `cdQueryAudit`。数据校验不通过时禁止部署。

### 问题 18：明细表缺少汇总行或汇总行位置错误

- **现象**：明细表没有汇总行，或汇总行出现在分页数据底部，导致用户无法快速核对整体金额。
- **根因**：页面只渲染分页后的数据行，或把汇总行当作普通数据参与分页与排序。
- **修复**：基于当前筛选后的全量结果计算汇总，固定渲染在表头下第一行；账单、预算、超支金额求和，消耗进度按汇总账单/预算及月份时间进度重算，CD 名称与 CD 执行率展示 `-`。

### 问题 19：顶部指标卡与 BABI 页面金额不一致

- **现象**：顶部 KPI 指标卡或趋势图中的账单、预算与 BABI 页面同条件查询结果存在差异。
- **根因**：错误地使用 `cost detail`、`tableRows` 或 `productRows` 的明细求和生成概览数据；明细接口与 BABI 页面成本概览存在口径差异。
- **修复**：报告覆盖期内逐月调用 `budget consumption cost overview get`，将其 `BillAmount`、`BudgetAmount`、`ConsumptionRate`、`TimeRate` 写入 `overview` 和 `trend`；明细接口仅用于维度下钻。逐月核对不一致时禁止部署。

## 输出前校验

### 数据与计算校验

- 已确认唯一预算单元稳定 ID。
- 账期恰好包含当前月和前 11 个月。
- 预算版本来自实时版本列表，不是硬编码。
- 所有查询使用同一套区域、版本、账期、预算单元和金额口径。
- 报告覆盖期内已逐月查询成本概览；`overview`、顶部 KPI 指标卡和 `trend` 的账单/预算与 `cost overview` 逐月返回值一致，未使用明细行求和替代。
- 概览、Top 商品和明细已完成分页或明确说明接口自身 Top 限制。
- 当前月与历史月使用不同的时间进度口径。
- 累计超支只累加正值，未用节余冲抵超支。
- 子预算单元来自"需求方预算单元"，未与商品预算单元混淆。
