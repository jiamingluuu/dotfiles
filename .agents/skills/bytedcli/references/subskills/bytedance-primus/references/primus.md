# Primus API Notes

## Host Routing

- Focused Primus application summary, role, pod, Data, and log-file queries use the dedicated regional `/cli` resource API first on all four sites. Focused log discovery expands a validated pod landing when necessary and falls back serially to retained History when the regional path cannot produce readable concrete files. `primus export` remains History-backed for role rows and log-index discovery.
- History-only resources continue to use `primushistory` / `primus-history` hosts. When `--url` receives a human `primus-ui` URL, bytedcli canonicalizes it to the matching History base to derive the region, application id, attempt, and retained endpoint paths; only `primus url get --kind ui` intentionally returns a UI URL.
- CN VDCs such as `GL`, `HL`, `LF`, `YG`, `DY`, `YX`, `LQ`, and `ZC` use `*.byted.org` History hosts by default.
- Copied CN UI URLs such as `primus-ui-cn.byted.org/<cluster>/<app>/webapps/primus/` are routed by the cluster path suffix (`yx`, `gl`, `lq`, and similar) to `primushistory<suffix>-k8s.byted.org`. History requests should never keep the `primus-ui-cn` host.
- Recognized I18N ROW VDCs such as `USWest2`, `Maliva`, `MY2`, and `SG1` automatically use matching ROW resource and History hosts, for example `primushistoryuw2-k8s.tiktok-row.org`; `--row` remains an explicit compatibility selector. Copied ROW UI URLs such as `primus-ui-maliva.tiktok-row.org/<cluster>/<app>/webapps/primus/` are routed by the cluster path suffix (`maliva`, `useast1b`, `my2`, `uswest2`, and similar). Older copied ROW History URLs such as `primushistoryuw2.tiktok-row.org` are normalized to the matching `-k8s` History host.
- US-TTP / `useast5` application discovery uses the office History service, while app-specific `newStatus.json?from=page` stays on the Forge-provided `primushistoryuseast5-k8s.tiktok-us.net` host. Normalize copied `primushistoryuseast5-k8s.tiktok-usts.net` input to the resolvable `tiktok-us.net` form. Application summary, roles, pods, Data, and focused log-file discovery use the regional `/cli` resource API. AM env remains on `primus-history-usttp.tiktok-row.org`; do not generalize that env exception into a global app-resource alias. For an exact retained app payload, use one read-only `curl --compressed` request against the direct host, write it to a mode-0600 temporary file rather than stdout, register an `EXIT` cleanup trap before the request, and require valid object-shaped JSON before inspecting requested keys. Redirects, login/error pages, invalid JSON, and non-object JSON mean transport/auth/format unavailable or unverified, not empty data.
- EU-TTP / `useast2a` uses its regional `/cli` endpoint for application summary, roles, pods, Data, and focused log-file discovery. Exact app payloads such as `newStatus.json?from=page` preserve the Forge-provided `primushistoryuseast2a-k8s.tiktok-eu.org` host. AM env remains on `primus-history-euttp.byted.org`; do not rewrite app payloads to that BDEE host. A regional log landing uses its configured office alias while concrete file URLs remain canonical. For an exact retained app payload, use one read-only `curl --compressed` request against the direct host, write it to a mode-0600 temporary file rather than stdout, register an `EXIT` cleanup trap before the request, and require valid object-shaped JSON before inspecting requested keys. Redirects, login/error pages, invalid JSON, and non-object JSON mean transport/auth/format unavailable or unverified, not empty data.
- EU-TTP and US-TTP History frontends embed `./timeline.html` and `./taskbuild.html`; those pages call same-origin relative `doctor/timeline.json` and `doctor/taskbuild.json`. Authenticated browser verification currently cannot load usable data from these pages. Treat Timeline/TaskBuild as unavailable agent resources in those two regions: do not call a raw endpoint, switch to a direct/gateway alias, or convert the failure into an empty result. CN/ROW keep their normal CLI query path.
- Yarn `application_...` ids do not map cleanly from VDC. Pass `--url` or an explicit `--host` with the matching History host.
- `--url` and `--host` are intentionally limited to known Primus History/UI host forms. For Primus logs, do not hand-build log paths; use `primus log list --resolve-files` for bounded file metadata or `primus log get` for content so bytedcli can bind discovery to the selected application, pod, and host coordinates.
- Primus History selects attempts through the path form `/jobhistory/app/<app-id>/<attempt-id>/`, not through a query parameter. Use `--attempt-id <n>` with normal URLs or generated app ids; copied History view URLs in the path form are also valid `--url` inputs. bytedcli applies the same attempt to resource API queries and preserves the numeric segment for retained History env, status, task, DevOps, and relative endpoint routes.

## App IDs

- CloudNative Primus app ids usually look like `nj-demo-pj`.
- If the user gives `CLOUDNATIVE_APPLICATION_ID` without `-pj`, bytedcli appends `-pj` automatically for History paths.
- Yarn app ids beginning with `application_` are preserved as-is.

## Data Endpoints

- `primus app list` fetches `/ws/v1/history/list` from the History root and normalizes recent application rows. Filters are applied to the bounded response and `truncated` indicates that the requested History limit was reached.
- `primus app get` returns normalized application/AM facts, role counts, related applications, Data streams, Streaming sources, gang-scheduler queue entries, actual `overviewSections`, relative `queryableResources` command paths, application `features`, safe component versions, and structured `endpointErrors`. A focused resource may remain queryable even when the overview endpoint omits its payload; prepend `bytedcli primus` to the returned path and reuse the current `--url` or `--vdc` / `--app-id` selector to determine whether records are empty. Raw env/overview/status are included only with `--raw`; status is otherwise fetched only as an overview fallback. `--expect-job-id` and `--expect-stage-id` validate AM env context and fail closed if env is unavailable.
- On all four regions, `primus am get`, `primus data get`, `primus role list`, and the core normalized fields of `primus app get` use the resource API. Focused AM/Data/role queries retry through retained History for the same application/attempt when the regional provider times out, returns HTTP 408/429/5xx, or returns an unusable provider/schema response. Successful empty responses remain authoritative; input, auth/permission, context-mismatch, and not-found errors do not trigger fallback. History still enriches `app get` with env/overview/status evidence. Data fields may arrive as `#<JSON>#`; bytedcli removes exactly one matching wrapper before parsing. A genuinely empty US/EU Data response still falls back to retained History Data.
- `primus config get`, `primus job get`, and `primus streaming get` read the Primus UI `newStatus.json?from=page` payload.
- `primus env get` fetches `env/environment.json`, supports `--key` / `--prefix`, and redacts secret-like values unless `--show-sensitive` is set.
- `primus cluster get` fetches `cluster.json`.
- On all four regions, `primus pod list` uses the BAM v1.0.4 resource route `/cli/pods/:appId[/:attempt]?role=...` and retries the matching retained History role page when that provider is unavailable under the same guarded error policy. A successful empty pod page does not fall back. Focused `primus log list/get` use that pod route plus `/cli/logs?podName=...&ip=...` first, resolve a validated pod landing when file metadata is absent, and retry serially through History when regional discovery still has no readable concrete files. `primus export` remains History-backed.
- `primus task list` fetches the task table via `role=task`.
- On CN/ROW, `primus task-build list` fetches and normalizes `doctor/taskbuild.json` pagination.
- On CN/ROW, `primus timeline list` fetches and normalizes `doctor/timeline.json` pagination.
- `primus doctor get` fetches the aggregate Doctor payload from `doctor/status.json` and redacts secret-like Doctor environment entries unless `--show-sensitive` is explicit.
- `primus flow get` fetches `primus_flow/status.json`.
- `primus devops crd list` fetches CRDs from `doctor/status.json?onlyCr=true`.
- `primus devops pod list`, `primus devops lifecycle get`, and `primus devops pod-status get` fetch pod diagnostics from the DevOps / UI status endpoints. `devops pod list --table-mode search` selects the cross-status search table; `--table-mode missing` selects the missing-pod table; `normal` is the default.
- `primus raw get --kind <kind>` is for exact endpoint checks when a task explicitly needs the raw JSON shape.

## Logs

- Pod rows may expose a `logUrl`; do not guess `/log/<pod>.log` or a synthetic `logs-index.json` path.
- Use `primus log list --resolve-files` to enumerate concrete files without reading their content. It defaults to one row page and five resolution attempts. All four sites prioritize abnormal rows with usable pod/host coordinates and use the regional file API first; `logSource: "primus-cli-landing"` means a validated pod landing supplied the concrete files. When regional discovery still has no concrete files, bytedcli falls back serially to retained History landing/redirect discovery and accepts History proxy `code` 0 or 1 as successful transport outcomes. JSON distinguishes `truncated` from `resolution_truncated` and includes `page_size`, `attempted_rows`, `resolved_rows`, `concrete_file_rows`, `landing_only_rows`, `no_files_rows`, `failed_rows`, `skipped_rows`, `without_log_url_rows`, and `without_log_coordinates_rows`. The top-level `cache` object reports `hit`, `miss`, `mixed`, or `bypass`; every lookup records its cache write time, current age, expiry, and TTL when available. Ordinary `log list` also caches its regional pod discovery; explicit `pod list` remains uncached.
- `resolved_rows` counts resolution attempts that completed without a transport error; it does not mean every row had concrete files. Use `concrete_file_rows`, `landing_only_rows`, and `no_files_rows` for that distinction.
- Use `primus log get` to fetch concrete files such as `stderr.log`, `syslog.log`, `stdout.log`, or role-specific logs under `/var/log/tiger`. It prioritizes abnormal rows and automatically tries up to three candidates when content is empty or unavailable. One concrete file failure is recorded in `fetchError`, with `fetchErrorCode`, `fetchErrorHint`, and `fetchErrorAuthCommand` retained when available, and does not stop the remaining matches. Inspect `rowAttempts`, `scan`, and `cache` to see exactly what was tried. `--no-cache` bypasses the regional pod/file discovery cache and EU/US plugin metadata cache for that invocation; concrete log bodies remain live and are never cached. All four sites use regional pod/file discovery first and retained History only as a serial fallback; US-TTP/EU-TTP select the content transport internally and retain Footprint when no optional transport is available. Keep using `primus log get` after discovery instead of handing concrete URLs to another log command. `--start <range>` controls byte ranges. `--output-dir` writes matched content to files; `--download-full` downloads US/EU files and direct CN/ROW files only when discovery supplied a positive file size.
- `logResolutionStatus: "no-files"` is emitted only after every applicable discovery source completes successfully with an empty concrete-file list. `logResolutionStatus: "fetch-error"` means discovery failed and must not be interpreted as an empty list.
- If the result has `logResolutionStatus: "landing-only"`, bytedcli could not resolve concrete file links for the selected row. Try a more specific `--pod-name`, a different `--row-index`, or a narrower `--file-pattern` before reporting that logs are unavailable.
- History retention can make regional log fallbacks, History-only resources, or `primus export` role rows unavailable. Use the exact older application/attempt from `app get`'s `applications` field or upstream stage metadata; never substitute the latest application without validating job/stage context.

## Response Handling

- Primus History JSON endpoints may return gzip bytes even when response headers are incomplete. The Primus client handles gzip magic bytes before JSON parsing.
- Primus control endpoints may return HTTP 200 with an application-level rate-limit message. The client retries boundedly and raises `PRIMUS_RATE_LIMITED` with guidance when exhausted.
- EU-TTP gateways may report gzip in headers while returning plain JSON; do not add extra manual decompression around bytedcli output.
- Share normalized `app get` findings instead of raw environment payloads; `app get --raw`, `env get --show-sensitive`, `doctor get --show-sensitive`, and `primus export` can contain sensitive runtime values.

## Exit Diagnostics

- `0` and `-1000` are usually normal exits.
- `137`, `-137`, `9`, and `-9` usually mean OOM or kill unless `diag` gives a more specific cause.
- For HDFS permission or host allowlist issues, inspect AM env fields such as pod name, host IP, IPv6, resource group, and hostname.
