# XPA 专属 troubleshooting（bytedcli）

## 鉴权 / 登录

| 症状                                                      | 处理                                                                                                                                                                                     |
| --------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `请重新执行：xpa auth login` 或 `xpa_token: missing`      | 跑 `bytedcli xpa auth login`。命令复用 bytedcli 的 ByteCloud 登录态；如果 `bytedcli auth status` 也是未登录，先跑 `bytedcli auth login`。                                                |
| `refresh xpa token failed`                                | 已自动降级回退到 exchange；只在 exchange 也失败时才抛错。后端 refresh 路由在 ppe 曾漏部署（boe / prod 正常），如果只发生在 ppe，跟后端确认 `/user/refresh-xpa-token` 在 ppe 的部署状态。 |
| 网关返回 `code:401, message:"not login"`（HTTP 200 JSON） | 多半是路径前缀走错——请求被 web BFF 截胡。检查是否误设 `BYTEDCLI_XPA_PATH_PREFIX=/api`。prod 已迁到根（pathPrefix 空），boe / ppe 同理。                                                  |

## env / 泳道

| 症状                                        | 处理                                                                                                  |
| ------------------------------------------- | ----------------------------------------------------------------------------------------------------- |
| BOE 跑命令 404（路由未注册）                | 网关只在特性泳道部署。加 `--xpa-tt-env <feature-lane>`。基准环境一旦部署完成可去掉。                  |
| BOE 带 `--xpa-tt-env` 反而 401/某些命令异常 | 用对照法：分别加 / 不加 `--xpa-tt-env` 两次 curl 同接口比对响应；常见是 SSO 在该泳道有差异。          |
| prod 走 ppe 路由（或反过来）                | `--xpa-env prod` / `--xpa-env ppe` 选错。ppe 共用 prod host，靠 `x-use-ppe: 1` 染色；不要手工 unset。 |

## 输入 / 校验

| 症状                                                                                                  | 处理                                                                                                                                                                                        |
| ----------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `--id must be a positive integer` / `--device-ids must be a positive integer: ...`                    | 本地强校验。所有 ID 是正整数字符串（int64 保精度），不要传 `0` / 负数 / 含字母。                                                                                                            |
| `device locator: pass exactly one of --device-id / --serial-number / --instance-name / --instance-id` | mobile 只接受前两个；pc 四个里恰好一个。多传或全空都拒。                                                                                                                                    |
| `lark-file-url must be a Lark sheet URL`                                                              | `xpa task create --lark-file-url` 必须是 Lark sheet URL（路径含 `/sheets/`）；docs/wiki URL 不被接受。                                                                                      |
| `Exactly one task data source is required`                                                            | `xpa task create` 必须在 `--lark-file-url` 与 `--jsonl` 中恰好选择一个。                                                                                                                    |
| `Inline JSONL is too large`                                                                           | inline 文本超过 5 MiB；缩小内容后重试。                                                                                                                                                     |
| Gateway 返回 `70024 JSON Lines文件解析错误`，或提示 JSONL 行号、大小限制                              | 先对照所选 workflow 开始节点的输入定义，核对每行是否包含必需字段，尤其是字段名；再检查每个非空行是否为合法 JSON object，以及总行数是否超过 5000、单行是否超过 1 MiB。按错误行号修正后重试。 |
| `--execute-start-from must be a positive integer` 等                                                  | 时间范围是**秒级 Unix 时间戳**正整数；JS 习惯的毫秒值会被本地拒（拿到 1719158400000 这种除以 1000）。                                                                                       |

## 网关返回 / 调试

| 症状                                                                                  | 处理                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| ------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `AppError` code `XPA_API_ERROR` 带 `logid`                                            | text 模式展示服务端 message，并在独立 `Diagnostics` 行列出实际存在的 HTTP 状态、业务码与 `logid`；JSON 模式从 `error.status_code`、`error.request_id`、`error.details.bizCode/logid` 读取。拿 logid + 对应 PSM（xpa 网关或鉴权 PSM，向 xpa 后端团队确认）到 argos / webshell 按日志查。                                                                                                                                                                                                  |
| 返回 HTML 而非 JSON（5xx / 后端实例挂）                                               | 错误信息会区分「服务器错误页」 vs 「web 前端 SPA 兜底页」。前者按 logid 找后端；后者多半是 env / path prefix 配错。                                                                                                                                                                                                                                                                                                                                                                      |
| 大整数 ID 在 `--json` 输出里看着像 number 但精度不对                                  | 检查 logid + 上游字段。client 已在 JSON.parse 前给超安全范围的裸整数加引号转字符串；数组相邻整数走零宽断言正则，不应漏。若仍异常，只提供 logid 和脱敏后的最小异常字段片段（保留字段名 / 类型，值用掩码替代）；不要附完整原始响应。                                                                                                                                                                                                                                                       |
| 写命令不带 `--yes` 没真发出去                                                         | 设计如此（CI 安全）：写命令默认 dry-run。看到 `[dry-run] ... Re-run with --yes to execute.` 后，加 `--yes` 重跑即真发。无 `--dry-run` flag，也无交互式确认；CI 与 TTY 行为一致。                                                                                                                                                                                                                                                                                                         |
| `marketplace components` 有某设备类型的节点，但同条件 `meta-node list` 为空或数量不同 | 两条命令对应不同下游查询视图：前者是 marketplace 分类树，后者是独立的权限范围 MetaNode 列表，权限与发布状态边界不保证一致。这不是 CLI 在本地交叉过滤。需要组件目录当前可见的完整结构时，以 `bytedcli --json xpa workflow marketplace components --level atomic --device-type cloud` 形式重跑原查询；不要把 components 的 ID 当作必然能被 `meta-node list` 命中的详情入口。若需后端确认差异，只提供脱敏后的筛选条件、两边计数和可用 logid；不要粘贴完整 JSON、token、用户标识或节点配置。 |

## 历史迁移

| 情形                                                                                                                                                           | 处理                                                                                                                                                                                                                                                                                                                                                        |
| -------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 之前用 `xpa <cmd>`（独立包 `@bytedance-dev/xpa-cli`）                                                                                                          | 改 `bytedcli xpa <cmd>`，业务能力对齐独立包 1.1.19；CLI 表面按 bytedcli 规范调整，具体差异见下表。                                                                                                                                                                                                                                                          |
| 旧 `xpa <cmd> --dry-run` 脚本迁过来报 `error: unknown option --dry-run`                                                                                        | `--dry-run` flag 已移除（对齐 bytedcli `bytecycle` 等同类写命令域的范式）。**不带 `--yes` 即为 dry-run**——脚本里把原来的 `--dry-run` 去掉即可；真实执行加 `--yes`。`--yes` 行为与旧版一致。影响范围：所有写命令（`task start/pause/stop`、`task subtask stop`、`task device add/remove/export-result`、`device unbind/delete`、`dataset reset/rerun`）。    |
| 旧 `xpa device list --device-status 1` / `--connect-type 2` 等数字 enum                                                                                        | 已改成语义值：`--device-status <online\|offline>` / `--device-use-status <idle\|busy>` / `--connect-type <adb\|link>` / `--device-platform <private\|public\|cloud>`。原因：数字 enum 强迫用户和 Agent 翻文档才知道 1/2 是什么。命令层会把语义值映射回后端的数字码（在 `src/cli/commands/xpa/device.ts` 顶部的几个 `*_MAP`）。                              |
| 旧 `xpa <cmd>`（不带任何 flag）在 TTY 进交互式 y/N 确认                                                                                                        | 交互式确认已移除（对齐 bytedcli 全域不写 readline 提示的约定）。不带 flag = 安静 dry-run（打印「Re-run with --yes to execute.」后退出 0），真实执行必须显式 `--yes`。                                                                                                                                                                                       |
| 旧 `xpa task devices-add` / `devices-remove` 字面拷过来报 `unknown command`                                                                                    | 改 `bytedcli xpa task device add` / `bytedcli xpa task device remove`。原 `devices-<verb>` 把动词嵌到名词里，违反 bytedcli「动词在最后一级」的命名硬约束；同 PR 内（首次落地，未发版）整体改成 `task device <verb>` 子树。选项语义与旧版完全等价。                                                                                                          |
| 旧 `xpa task subtasks` / `task subtask-stop` / `xpa health` / `dataset reset-failed` / `task get --no-full` 字面拷过来报 `unknown command` 或 `unknown option` | 同 PR 内一并对齐 bytedcli `CONTRIBUTOR_PATTERNS`：sub-resource 改子树 `task subtask list` / `task subtask stop`（动词在最后一级）；`xpa health` → `xpa system status`（命名空间下沉到 system）；`dataset reset-failed` → `dataset reset`（动词在最后一级，后端路由不变）；`task get --no-full` → `task get --brief`（避免双否定）。选项与旧版语义完全等价。 |
| 旧 `--env <env>` / `--tt-env <lane>`                                                                                                                           | 改为 `--xpa-env <env>` / `--xpa-tt-env <lane>`（域命名空间防撞）。环境变量同步 `XPA_ENV/XPA_TT_ENV` → `BYTEDCLI_XPA_ENV/BYTEDCLI_XPA_TT_ENV`。                                                                                                                                                                                                              |
| 旧 `~/.xpa/auth.json` 凭据                                                                                                                                     | 已弃用，凭据落 bytedcli 的 `AuthFileCache`（`bytedcliDataDir` 下，形如 `~/.local/share/bytedcli/data/xpa_token.<host>.json`，权限 0600）。重跑 `bytedcli xpa auth login` 即可。                                                                                                                                                                             |
| `xpa update` 命令                                                                                                                                              | 未移植——升级走 bytedcli 自身的 `bytedcli self update`。                                                                                                                                                                                                                                                                                                     |
