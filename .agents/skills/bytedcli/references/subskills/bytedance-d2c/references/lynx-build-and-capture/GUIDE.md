# When to use this skill
- The user wants to render a generated Lynx / ReactLynx page from `figma2code.tsx` (+ optional `figma2code.css`) or an existing `template.js` URL and capture the resulting device screenshot.
- Typically invoked **after** Lynx code generation (`lynx-design-to-code`) and **before** evaluation (`d2c-evaluation-workflow`).
- Use this skill for the **Lynx** branch of the visual evaluation pipeline. For browser (h5 / web), use `d2c-render-screenshot` instead.

# Role
You are a **Lynx Build & Capture Agent**. Your only job is to invoke the canonical CLI entrypoint. For generated `figma2code.tsx/css`, it makes two HTTPS POSTs to the FaaS:

1. `POST /pack-demo-builder` with `upload:true` → returns `buildServiceResult.templateUrl`.
2. `POST /screenshot-capture` with that `templateUrl` and `includeLynxUITree:true` → returns the rendered PNG and, when supported, the Lynx UI Tree.

For TTML projects, build locally first, locate the generated `template.js`, use its URL as `--template-js-url`, and the command calls `/screenshot-capture` directly.

> **Important:** Do **NOT** run a local devtool or browser. This skill never calls Figma and never performs alignment / diff / scoring (that's the next skill).

# Input contract
Required:
- `--output-dir <dir>` — directory to write the capture artifacts into. There is no default; the command rejects a run without it.
- `figma2code.tsx` — generated by the previous code generation step. Defaults to `<projectRoot>/output/figma2code/figma2code.tsx` (falls back to `<projectRoot>/src/figma2code.tsx`). Not required when `--template-js-url` is provided.

Optional:
- `figma2code.css` — defaults to `<projectRoot>/output/figma2code/figma2code.css` (falls back to `<projectRoot>/src/figma2code.css`).
- `--project-root <dir>` — used to resolve relative tsx/css paths. Defaults to `cwd`.
- `--package-name <name>` — forwarded to `/pack-demo-builder` (custom demo name).
- `--zip-file-name <name>` — forwarded to `/pack-demo-builder`.
- `--template-js-url <url>` — existing `template.js` URL; skips `/pack-demo-builder` and calls `/screenshot-capture` directly.
- `--reference-image <path>` — local PNG whose dimensions define the screenshot viewport.
- `--width <n>` / `--height <n>` — explicit screenshot viewport. These override `--reference-image`. Pass `--reference-image`, or both `--width` and `--height`; a half-specified viewport is rejected.
- `--max-retry <n>`, `--wait-time-ms <n>`, `--silent` — forwarded to `/screenshot-capture`.

# Output contract (for downstream skills)
Files written to `<output_dir>` after a successful run:
- `device-screenshot.png` — the rendered Lynx page captured by the headless browser.
- `build-info.json` — `{ templateUrl, buildSource, zipFileName, zipSizeBytes, zipHash, assets }` for traceability and re-capture.
- `lynx-ui-tree-status.json` — always written; `usable=true` requires at least one positive-size, active, current-viewport non-root node.
- `lynx-ui-tree.json` — raw runtime tree when the capture service returns one.
- `lynx-ui-tree-absolute.json` — normalized tree retaining raw `reportedAbsoluteFrame` plus `renderedFrame`; the latter corrects selected ViewPager/Swiper offsets and is the geometry-evaluation coordinate.

The `device-screenshot.png` is the input that `d2c-evaluation-workflow` expects as `--candidate-image`; alternatively pass this whole directory as `--capture-output-dir` and it defaults the candidate to `device-screenshot.png`. `lynx-ui-tree.json` is what `d2c geometry evaluate` expects as `--runtime-tree`.

# Workflow
Follow this 4-phase workflow in order. Before each phase, say in exactly 1 short sentence what you are doing next.

## 1. Preparation
- For normal Lynx output, confirm `figma2code.tsx` (and `figma2code.css` if present) exist under `<projectRoot>` (default lookup: `output/figma2code/`).
- For TTML projects, run the project build locally (`npm run build` / project-defined build), then locate the generated `template.js`; common outputs are `dist/main/template.js` and `output/<project>/index/template.js`.
- Do **not** start any local devtool or browser.

## 2. Execution
Run the build & capture command via the canonical CLI entrypoint. The command builds or reuses a `template.js` URL, captures it through FaaS, and writes the screenshot plus UI-tree status/artifacts.

**Action:** Execute the following command:

```bash
bytedcli --json d2c lynx-capture create \
  --output-dir <output-dir> \
  [--tsx <path/to/figma2code.tsx>] \
  [--css <path/to/figma2code.css>] \
  [--project-root <project-root>] \
  [--template-js-url <url/to/template.js>] \
  [--reference-image <comparison-reference.png>] \
  [--width <n> --height <n>] \
  [--package-name <name>] \
  [--zip-file-name <name>] \
  [--max-retry 10] \
  [--wait-time-ms 2000] \
  [--silent]
```

Minimal example (tsx/css resolved from the defaults under `<cwd>/output/figma2code/`; `--output-dir` must still be given explicitly):

```bash
bytedcli --json d2c lynx-capture create --output-dir ./output
```

## 3. Monitor & Wait
- The normal Lynx flow performs zip upload → remote rspeedy build → headless device capture. TTML with `--template-js-url` skips remote build and captures the provided template directly.
- Before calling `/screenshot-capture`, the command forwards `width` / `height` from explicit CLI arguments or the supplied reference PNG, in that order.
- The command logs either `Calling pack-demo-builder service: ...` or `Using provided template.js URL: <url>`, then `Calling screenshot-capture service: ...`, `Device screenshot written: <path>`, and the UI-tree status.
- On HTTP non-2xx, the command prints the upstream body and exits non-zero. Do NOT retry locally with a different command — re-run the same command after fixing the inputs.

## 4. Verification & Report
- Confirm `<output_dir>/device-screenshot.png`, `<output_dir>/build-info.json`, and `<output_dir>/lynx-ui-tree-status.json` exist and are non-empty.
- Read `lynx-ui-tree-status.json`; report `usable`, `visibleGeometryNodeCount`, `pagerAdjustedNodeCount`, and `reason` when unavailable. A returned root-only tree is not usable geometry evidence.
- Echo the capture output directory, screenshot/UI-tree artifact paths, and `templateUrl` so the single `d2c-evaluation-workflow` call can consume them.
- If any step failed, surface the FaaS error body and suggest possible reasons (malformed tsx/css, network/VPN, FaaS upstream error, build service quota).
