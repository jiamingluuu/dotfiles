# 字节内场 NAT（DCS）历史流量查询

通过 Pisces 查询已上报的内场自建 NAT 流记录。使用 ByteCloud 用户 JWT，与 nat egress get 相同；无需创建 Oncall、群聊或变更工单。

```bash
bytedcli --json --http-timeout-ms 45000 nat traffic get \
  --psm example.service.api --dst-ip 203.0.113.1 \
  --start 2026-09-01T00:00:00+08:00 --end 2026-09-01T00:01:00+08:00 \
  --protocol tcp --dst-port 443 --limit 200
# 可加 --source-ip 10.0.0.1、--vdc demo-vdc、--site boe
```

- PSM、目的 IP、带时区且精确到秒的起止时间必填；按连接创建时间查询 [start, end)，最长 24 小时。目的端口省略表示不限，显式传入须为 1–65535。
- 服务端同步查询最长 30 秒。历史查询客户端默认超时 45 秒，显式全局 `--http-timeout-ms` 或对应环境配置可覆盖；示例显式使用 45000 毫秒留出传输时间。超时仍是失败，不保证扩大超时就能查通，也不要自动扩大查询范围或重试。
- 返回全范围汇总和最多 1000 行明细，默认 200 行。JSON 保留所有统计量为十进制字符串，避免精度损失。
- truncated 为 true 时明细不完整，须缩小时间范围后分段查询；不能把当前明细导出当作完整数据。
- 结果是 NAT 流记录聚合，不是 HTTP 次数，不包含 URL 或 HTTP 状态码。未查到不证明未访问；上报延迟、留存和采集覆盖仍需核查。
- 历史查询不依赖当前 Running Pod；当前机器归属不能当作历史实例证据。
- 数据源未配置、无权限、超时或资源限制均为失败，不能当作零记录。保留 query_id 排障，不重试扩大查询范围。
- 服务端须先配置获批的只读查询身份；CLI 不转发本地 Aeolus 会话到 Pisces。
- 合入 CLI 不代表服务端已部署该接口或配置了数据源。HTTP 404 应检查目标环境版本；“查询通道未配置”应检查目标环境获批的只读连接，不能改用个人会话或其他环境身份绕过。
